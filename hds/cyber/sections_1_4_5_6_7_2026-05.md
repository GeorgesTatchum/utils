## 1. Résumé exécutif

Premier exercice de revue mensuelle Threat Intelligence OneOrtho. Sur la période 01/05/2026 au 22/05/2026, **116 items examinés** issus de 12 sources consultées avec succès et 3 sources nécessitant un rattrapage manuel (CISA ICS Medical, FDA Safety Communications, Packagist).

**12 items applicables individuels + 2 groupes consolidés** identifiés sur le stack OneOrtho :
- 8 items de priorité P2 (6 RCE Critical Windows Server + 2 CVE Symfony exposées internet),
- 5 items P3 individuels (XSS PHP-FPM, vulnérabilités Docker, 2 CVE MariaDB CVSS ≥ 7) + 62 CVE Windows Server Important traitées en groupage P3,
- 1 groupage P4 (8 CVE MariaDB CVSS < 7, à traiter via la même montée de version que les P3 MariaDB).

**Aucun item P1** : aucune CVE applicable au stack OneOrtho n'est actuellement dans le catalogue CISA KEV. Deux CVE Microsoft Defender ajoutées au KEV le 20/05/2026 sont en investigation (applicables si Defender est l'antivirus utilisé sur les serveurs Windows OneOrtho).

**Décisions clés** : (1) appliquer le Patch Tuesday Windows Server du 12/05/2026 sur l'ensemble du parc sous J+14 ; (2) monter `symfony/runtime` et `symfony/routing` sous J+14 ; (3) plan unique de montée MariaDB sur 4 branches LTS (11.8.7, 11.4.11, 10.11.17, 10.6.26) sous J+30.

## 4. Tendances observées

Le mois de mai 2026 a vu **trois publications groupées** de vulnérabilités sur la stack OneOrtho :
- **Symfony Security Advisory du 20/05/2026** : 10 CVE en un même batch, dont 3 applicables au portail (composants `symfony/runtime`, `symfony/routing`, `symfony/security-http`). Le batch est dominé par des composants non utilisés (`mailer`, `notifier`, `html-sanitizer`, `json-path`), ce qui démontre l'intérêt de la traçabilité §3.3 des items non applicables.
- **PHP Security Advisory du 07/05/2026** : 9 CVE dont 3 SOAP (non applicables, OneSoftware n'utilise pas SOAP). Reste 6 CVE PHP-FPM / mbstring / urldecode / DOMNode dont 4 à investiguer pour confirmer l'usage effectif des fonctions vulnérables.
- **Microsoft Patch Tuesday du 12/05/2026** : 68 CVE distinctes sur Windows Server 2016/2019/2022/2025, dont 6 RCE Critical. Le parc OneOrtho hétérogène (4 versions Windows Server cohabitent) augmente la surface d'attaque mensuelle. À chaque Patch Tuesday, le volume sera de cet ordre.

**Point d'attention récurrent** : le parc **MariaDB** OneOrtho compte 16 instances réparties sur 4 branches LTS (11.8, 11.4, 10.11, 10.6). Une seule CVE applicable au stack pèse mécaniquement comme 16 actions de patch. Ce levier d'amplification justifie l'industrialisation de la mise à jour MariaDB sur tout le parc.

**Sources non scrapables** : trois sources publiques (CISA ICS Medical, FDA Safety Communications, Packagist Security Advisories) restent inaccessibles via outils automatisés. Sans agrégateur RSS (en cours de mise en place), la consultation manuelle introduit un risque d'oubli. La mise en service de FreshRSS sera une priorité.

**Hétérogénéité des versions stack frontend** : confirmation que les modules Angular utilisent quatre versions de Three.js et deux versions d'Angular (20.3 vs 21.2). Pas de CVE applicable sur les modules ce mois, mais cette hétérogénéité reste un risque IEC 62304 §6.1 à porter en recommandation.

## 7. Recommandations pour le mois suivant

### Côté plan et processus

1. **Compléter §2.2 du plan** : préciser les versions courantes utilisées en production (PHP, Symfony, Angular, Three.js, Windows Server, MariaDB, MongoDB, IIS) ainsi que leurs dates EOL connues. Le fichier `curent-mariadb-onserver.md` est un bon point de départ pour MariaDB ; à étendre aux autres composants.
2. **Mettre à jour les URL §3.2 et §3.3** :
   - FDA Safety Communications : URL inscrite au plan retourne HTTP 404, à corriger.
   - MariaDB : remplacer `https://mariadb.org/about/security/` par l'URL GitHub raw `https://raw.githubusercontent.com/mariadb-corporation/mariadb-docs/main/server/security/cve/community-server.md`.
3. **Tracer un item récurrent ARCH-VERSIONS-CONVERGENCE** : l'hétérogénéité Angular 20.3 vs 21.2, Three.js 0.150 → 0.182 et le parc MariaDB à 4 branches LTS complique la veille et la remédiation. À inscrire en suivi mensuel jusqu'à convergence.

### Côté outillage

4. **Mettre en place FreshRSS** (instance self-hosted, cf. `procedure_agregateur_rss.md`) pour automatiser la consultation des sources accessibles uniquement en RSS et limiter les oublis sur les sources non scrapables.
5. **Industrialiser l'export MSRC** : la méthode CSV manuelle a fonctionné ce mois mais demande un effort répété. Étudier l'API officielle `https://api.msrc.microsoft.com/cvrf/v3.0/` pour un export programmé en début de chaque mois post-Patch Tuesday.
6. **Démarrer l'évaluation Dependency-Track** en remplacement progressif de Snyk sur le volet SCA, en cohérence avec la souveraineté des données SBOM. Cible : déploiement courant Q3 2026.
7. **Mettre en place un suivi automatisé du fichier MariaDB GitHub raw** : abonnement webhook sur les commits du fichier `server/security/cve/community-server.md` pour être notifié des ajouts de CVE.

### Côté gouvernance et compétences

8. **Formaliser une convention de datation** pour les CVE issues de sources sans date individuelle (MariaDB notamment). Convention proposée : utiliser la date de release MariaDB associée aux versions corrigées (récupérable sur le site officiel) à défaut de date NVD.
9. **Activer l'accès H-ISAC** si pertinent, ou décider explicitement de retirer cette source du §3.2 du plan.
10. **Documenter la procédure de notification clients/distributeurs OEM** (cf. plan §4 et §5) en cas d'item applicable P1/P2 avec impact fonctionnel client. À préparer en prévention même si aucun cas ne s'est présenté ce mois.
