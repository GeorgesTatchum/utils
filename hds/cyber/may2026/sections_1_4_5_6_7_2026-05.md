## 4. Tendances observées

Le mois de mai 2026 a été **particulièrement chargé** en publications groupées sur la stack OneOrtho :

- **Symfony Security Advisory** : trois batches successifs en mai. Le 20/05 (10 CVE dont 3 applicables aux composants `runtime`, `routing`, `security-http`). Le 27/05 (3 CVE Twig sandbox bypass, applicables car `twig/twig` présent). Le 29/05 (7 CVE sur `symfony/ux-*`, non applicables car UX absent du composer.lock). La traçabilité §3.3 fait ressortir 14 CVE Symfony écartées sur le mois pour 6 applicables — démontre l'intérêt méthodologique d'examiner systématiquement les batches éditeur.
- **PHP Security Advisory du 07/05/2026** : 9 CVE PHP-src. 3 CVE SOAP écartées (OneSoftware n'utilise pas SOAP). 4 CVE en investigation (urldecode, mb_convert_encoding, DOMNode::C14N, mb_check_encoding) — applicabilité dépendante de l'usage interne, à conclure cette semaine.
- **Angular Security Advisory du 28/05/2026** : 7 advisories d'un coup, dont 2 applicables runtime (DoS digitsInfo, XSS Template/Dynamic Component). 4 advisories non applicables runtime (Service Worker, HttpTransferCache SSR, platform-server) confirment que les modules OneOrtho utilisent un sous-ensemble restreint d'Angular. 2 advisories sur l'extension VS Code Angular Language Service (dont 1 Critique 23/05) à traiter en parallèle côté poste dev.
- **Microsoft Patch Tuesday du 12/05/2026** : 68 CVE distinctes sur Windows Server 2016/2019/2022/2025, dont 6 RCE Critical. Le parc OneOrtho hétérogène (4 versions Windows Server cohabitent) augmente la surface d'attaque mensuelle.
- **MariaDB** : évolution majeure entre mi-mois et fin de mois. **Trois CVE supplémentaires** ajoutées au document de référence, dont **CVE-2026-49261 CVSS 10.0** — le score maximal observé sur la période. Une nouvelle release MariaDB est sortie (11.8.8 / 11.4.12 / 10.11.18 / 10.6.27) qui devient la cible de la montée de version planifiée.

**Point d'attention récurrent** : le parc **MariaDB** OneOrtho compte 16 instances sur 4 branches LTS. Chaque CVE applicable pèse mécaniquement comme 16 actions de patch. Le plan de montée unique vers la dernière LTS de chaque branche reste la stratégie la plus efficace pour résoudre simultanément les 9 CVE 2026 listées.

**Sources non scrapables** : trois sources publiques (CISA ICS Medical, FDA Safety Communications, Packagist) restent inaccessibles via outils automatisés. La mise en service de FreshRSS reste une priorité haute pour les rapports de juin et au-delà.

**Hétérogénéité des versions stack frontend** : confirmée par le batch Angular du 28/05. Les 4 planificateurs OneOrtho utilisent Angular 20.3 (3 modules) et Angular 21.2 (Shoulder3D). Les correctifs devront être appliqués séparément sur chaque branche Angular, multipliant l'effort de patch. Ce risque IEC 62304 §6.1 demeure prioritaire à traiter via le ticket ARCH-VERSIONS-CONVERGENCE.

**Aucune CVE n'a fait son entrée au catalogue CISA KEV sur composant du stack OneOrtho** durant le mois. Les 2 CVE Microsoft Defender KEV ajoutées le 20/05 restent en investigation côté équipe infrastructure (Defender utilisé ou pas sur les serveurs OneOrtho).

## 7. Recommandations pour le mois suivant

### Côté plan et processus

1. **Compléter §2.2 du plan** : préciser les versions courantes utilisées en production (PHP, Symfony, Angular, Three.js, Windows Server, MariaDB, MongoDB, IIS) ainsi que leurs dates EOL connues. Le fichier `curent-mariadb-onserver.md` est un bon point de départ pour MariaDB ; à étendre aux autres composants.
2. **Mettre à jour les URL §3.2 et §3.3** :
   - FDA Safety Communications : URL inscrite au plan retourne HTTP 404, à corriger.
   - MariaDB : remplacer `https://mariadb.org/about/security/` par l'URL GitHub raw `https://raw.githubusercontent.com/mariadb-corporation/mariadb-docs/main/server/security/cve/community-server.md`.
3. **Tracer un item récurrent ARCH-VERSIONS-CONVERGENCE** : l'hétérogénéité Angular 20.3 vs 21.2, Three.js 0.150 → 0.182 et le parc MariaDB à 4 branches LTS complique la veille et la remédiation. À inscrire en suivi mensuel jusqu'à convergence.

### Côté outillage

4. **Mettre en place FreshRSS** (instance self-hosted, cf. `procedure_agregateur_rss.md`) pour automatiser la consultation des sources accessibles uniquement en RSS et limiter les oublis sur les sources non scrapables.
5. **Industrialiser l'export MSRC** : la méthode CSV manuelle a fonctionné ce mois mais demande un effort répété. Étudier l'API officielle `https://api.msrc.microsoft.com/cvrf/v3.0/` pour un export programmé en début de chaque mois post-Patch Tuesday.
6. **Démarrer l'évaluation Dependency-Track** en remplacement progressif de Snyk sur le volet SCA, en cohérence avec la souveraineté des données SBOM. Cible : déploiement courant Q3 2026.
7. **Mettre en place un suivi automatisé du fichier MariaDB GitHub raw** : abonnement webhook sur les commits du fichier `server/security/cve/community-server.md` pour être notifié des ajouts de CVE.

### Côté gouvernance et compétences

8. **Formaliser une convention de datation** pour les CVE issues de sources sans date individuelle (MariaDB notamment). Convention proposée : utiliser la date de release MariaDB associée aux versions corrigées (récupérable sur le site officiel) à défaut de date NVD.
9. **Activer l'accès H-ISAC** si pertinent, ou décider explicitement de retirer cette source du §3.2 du plan.
10. **Documenter la procédure de notification clients/distributeurs OEM** (cf. plan §4 et §5) en cas d'item applicable P1/P2 avec impact fonctionnel client. À préparer en prévention même si aucun cas ne s'est présenté ce mois.
